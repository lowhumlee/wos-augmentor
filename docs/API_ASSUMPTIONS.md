# API assumptions — Web of Science Expanded API & InCites API

Every assumption used by this tool is listed here and marked:

* **VERIFIED-FROM-DOCS** – confirmed against the official Clarivate OpenAPI/Swagger definitions,
  which were downloaded live for this project and are committed in this repository:
  * `docs/wos_openapi_snapshot.json` ← `https://developer.clarivate.com/apis/wos/swagger`
    (title: *Web of Science Expanded API*, version `1.0.0-oas3`, server `https://api.clarivate.com/api/wos`)
  * `docs/incites_openapi_snapshot.json` ← `https://developer.clarivate.com/apis/incites/swagger`
    (title: *InCites Document Level Metrics API*, version `2.0`, server `https://incites-api.clarivate.com/api/incites`)
  * A human-readable digest of both specs is in `docs/api_provenance.md`.
* **NEEDS-CHECK** – not fully pinned down by the published definition; isolated in
  `config/api_map.yaml` so it can be corrected without touching code, and/or verified at runtime
  by the `discover` / `count` commands (which print what the live service actually returns).

## 1. Authentication & transport

| # | Assumption | Status | Evidence / mitigation |
|---|------------|--------|-----------------------|
| 1.1 | Both APIs authenticate with an API key sent in the HTTP header `X-ApiKey` (OpenAPI `securitySchemes.key`: `type: apiKey, in: header, name: X-ApiKey`). | VERIFIED-FROM-DOCS | Both snapshots. |
| 1.2 | WoS base URL is `https://api.clarivate.com/api/wos`; InCites base URL is `https://incites-api.clarivate.com/api/incites`. | VERIFIED-FROM-DOCS | `servers[].url` in each snapshot. |
| 1.3 | JSON responses are obtained with `Accept: application/json` (both APIs also expose XML variants via `/xml` vs `/json` path segment on InCites and `application/xml` content type on WoS). | VERIFIED-FROM-DOCS | `content` keys in both snapshots. |
| 1.4 | Unauthenticated calls return HTTP 401 with body `{"message":"No API key found in request","request_id":...}` (observed live during development). | VERIFIED-FROM-DOCS (observed) | Mapped to a clear error message in `http.py`. |

## 2. Web of Science Expanded API — search & retrieval

| # | Assumption | Status | Evidence / mitigation |
|---|------------|--------|-----------------------|
| 2.1 | Search endpoint: `GET /?databaseId=WOS&usrQuery=<query>&count=<n>&firstRecord=<k>`; required params are `databaseId` and `usrQuery`. | VERIFIED-FROM-DOCS | `paths./` parameters. |
| 2.2 | `count` must be 0–100 (documented maximum = **100**); `count=0` returns only result-set metadata (used by `--dry-run`/`count`). | VERIFIED-FROM-DOCS | Param description: "Number of records to return, must be 0-100." |
| 2.3 | `firstRecord` may not be < 1 or > **100000** → per-query retrieval cap of 100,000 records; this is why Phase 1 splits by year/month. | VERIFIED-FROM-DOCS | Param description. |
| 2.4 | Response envelope: `{"Data": {"Records": {"records": {"REC": [ ... ]}}}, "QueryResult": {"QueryID", "RecordsSearched", "RecordsFound"}}`. | VERIFIED-FROM-DOCS | Schemas `WosSearchResponse`, `QueryResult`, `RetrieveResponse`. |
| 2.5 | Async pattern: first call returns `QueryResult.QueryID`; subsequent pages use `GET /query/{queryId}?count&firstRecord&sortField&viewField&optionView&optionOther&links`. | VERIFIED-FROM-DOCS | `paths./query/{queryId}`. |
| 2.6 | `GET /recordids/{queryId}` returns only UIDs (quota-cheap duplicate/coverage checks); `GET /id/{uniqueId}` retrieves one record by UID (`WOS:000123456700001`). | VERIFIED-FROM-DOCS | Paths + descriptions. |
| 2.7 | `edition` values for collection WOS: AHCI, CCR, IC, ISSHP, ISTP, SCI, SSCI, BHCI, BSCI, ESCI; multiple editions comma-separated; if omitted, user permissions are substituted. | VERIFIED-FROM-DOCS | Param description. |
| 2.8 | `publishTimeSpan` format `yyyy-mm-dd+yyyy-mm-dd` (e.g. `2019-01-01+2019-12-31`), mutually exclusive with `loadTimeSpan`/`createdTimeSpan`/`modifiedTimeSpan`. | VERIFIED-FROM-DOCS | Param description. |
| 2.9 | `optionView`: `FR` = full record (counts against quota), `SR` = short record **"that would not count against the quota"**, `FS` = field selection (auto when `viewField` is set). The SR view contains `static_data.summary.names.name[]` with `r_id`, `daisng_id`, `orcid_id`(present in FR; SR list shows `r_id`,`daisng_id`), `addr_no[]`, plus `dynamic_data.citation_related.tc_list_cc.dedup_total_count`. | VERIFIED-FROM-DOCS (schema); **NEEDS-CHECK**: whether `orcid_id` appears in the SR payload for every subscription — the tool therefore reads `orcid_id` defensively and can fall back to FR harvest (`harvest.view_mode: auto|sr|fr`). | Schemas `WosShortRecord` / `WosRecord`. |
| 2.10 | Author identifiers live at `static_data.summary.names.name[]`: `seq_no`, `role`, `full_name`, `display_name`, `wos_standard`, `last_name`, `first_name`, `addr_no[]` (may be scalar or list), `reprint`, `claim_status`, `preferred_name{}`, `r_id`, `orcid_id`, `daisng_id`, `data-item-ids.data-item-id{type,content}`. Single-element lists may arrive as objects → normalised by `record_fields.as_list()`. | VERIFIED-FROM-DOCS | Schema `WosRecord.static_data.summary.names`. |
| 2.11 | Addresses: `static_data.fullrecord_metadata.addresses.address_name[]` each with `address_spec.addr_no`, `full_address`, `organizations.organization[] {pref, content}`, `suborganizations.suborganization[]`, `city`, `country`, `street`. Author→address linking uses `name.addr_no[]` ↔ `address_name.address_spec.addr_no`. | VERIFIED-FROM-DOCS | Schema `fullrecord_metadata.addresses`. |
| 2.12 | Citation counts: `dynamic_data.citation_related.tc_list_cc.dedup_total_count` (WoS Core Collection total) and `tc_list_cc.function_tc[].local_count` with `func_class ∈ {CU, CR, CDE}` (uses-current / cites-usual / current-dynamic-extender). Per-silo counts in `tc_list.silo_tc[] {coll_id, local_count}`. Label always recorded as source=`WOS_CC_dedup_total_count` + retrieval timestamp. | VERIFIED-FROM-DOCS | Schema `dynamic_data.citation_related`. |
| 2.13 | DOI: `dynamic_data.cluster_related.identifiers.identifier[] {type, value}` with `type == "DOI"` (other observed types e.g. `ArtID`, `ISSN`, `ISBN`, `PII`, `PubMed ID`, `Agreement` are kept raw). | VERIFIED-FROM-DOCS (array shape); **NEEDS-CHECK**: exact spelling of `type` values across editions — matched case-insensitively and configurable (`identifiers.doi_type_value`). | Schema `cluster_related.identifiers`. |
| 2.14 | Publication identifiers: accession number `UT` = `UID` after the colon (`WOS:000123456700001` → `000123456700001`); edition info in `static_data.item.ids.content` (`WOS:000123456700001`) and `static_data.summary.EWUID.WUID.coll_id`; document types in `static_data.summary.doctypes.doctype[]` and normalized types in `static_data.fullrecord_metadata.normalized_doctypes.doctype`. | VERIFIED-FROM-DOCS | Schema. |
| 2.15 | Journal fields: `static_data.summary.titles.title[]` with `type ∈ {item, container, book}` (container = source title, `j` attribute = ISO abbreviation where present); volume/issue/pages/pubyear/coverdate/sortdate/early_access_* and open-access flag `pub_info.journal_oas_gold` ("Y"/"N") in `static_data.summary.pub_info`; ISSN/EISSN/ISBN under `static_data.item.ids`/`dyn identifiers` where exposed. | VERIFIED-FROM-DOCS (titles/pub_info/oas_gold); **NEEDS-CHECK**: ISSN/EISSN element naming in JSON differs between editions — read defensively from several candidate paths listed in `config/api_map.yaml` (`record_paths.issn_candidates`). | Schema walk of `WosRecord`. |
| 2.16 | Abstract: `static_data.fullrecord_metadata.abstracts.abstract.abstract_text.p` (or `.content`); keywords: `fullrecord_metadata.keywords.keyword[]`; Keywords Plus: `static_data.item.keywords_plus.keyword[]`; categories: `category_info.subjects.subject[] {ascatype:"WC"|"SC", content}`; research areas = `ascatype == "SC"`; language: `normalized_languages.language.content`; publisher: `summary.publishers.publisher.names.name.full_name` + `address_spec.full_address/city`; fund ack: `fullrecord_metadata.fund_ack.fund_text.p` + `grants.grant.grant_agency`; refs count: `fullrecord_metadata.refs.count`. | VERIFIED-FROM-DOCS | Schema. |
| 2.17 | Quota/rate headers: the API description states quotas are expressed in response headers, e.g. `X-REC-AmtPerYear-Remaining: 15467` and `X-REQ-ReqPerSec-Remaining: 3`. Exact full header set is not enumerated in the spec. | VERIFIED-FROM-DOCS (two examples); **NEEDS-CHECK**: additional headers (`X-REQ-ReqPerMin-Remaining`, etc.) → all `X-*` headers are logged and persisted per response; unknown ones never break the run. | `info.description` of WoS spec. |
| 2.18 | Rate limiting: HTTP 429 = "Throttle error" (documented response code). `Retry-After` header is **not** documented but is honoured if present. Backoff+jitter applied to 429/5xx/timeouts. | VERIFIED-FROM-DOCS (429 exists); NEEDS-CHECK (Retry-After semantics) | `responses["429"]`. |
| 2.19 | Query-length limit for `usrQuery` (GET URL length): not documented. Conservative default chunking keeps each built query ≤ 1800 characters and falls back to the async POST search (`POST /` with body `{databaseId, usrQuery, count, firstRecord,...}`) if a GET fails with 400/414. | NEEDS-CHECK → mitigated by config `limits.max_query_chars` + POST fallback (endpoint itself is VERIFIED-FROM-DOCS). | `paths./post`. |
| 2.20 | Result-set cap: no documented hard cap other than `firstRecord ≤ 100000`; community-reported practical caps (e.g. 1000/… for some endpoints) are treated as "split until retrieved == RecordsFound". The citation-report endpoint documents a 10K-record limit. | VERIFIED-FROM-DOCS (100000 offset bound, 10K citation-report note); practical behaviour → **runtime verification** by `count`/`harvest` completeness check (logged mismatches). | Param docs + citation-report description. |
| 2.21 | Identifier search tags for expansion: `RI="<ResearcherID>"` (quoted form `RI=(A-1234-2019)`), `OI="<ORCID>"` (e.g. `OI=(0000-0002-1825-0097)`), `DA="<DAIS ng id>"`. | NEEDS-CHECK — the WoS Expanded spec does not enumerate field tags; these are the tags shown in the Web of Science advanced-search documentation/UI and the `viewField` example "View ResearcherID or ORCID" confirms identifier-based retrieval exists. Mitigation: tag names live in `config/api_map.yaml → wos.query_tags` and `discover --verify-tags` runs a 1-record probe per tag and reports which are accepted by your subscription. | Spec does not list tags. |
| 2.22 | Organization/address field tags: `OG=` (Organization-Enhanced) primary route, `AD=` optional secondary route; boolean operators `AND/OR`, proximity `NEAR/N`, wildcard `*`, grouping `( )` supported by the query parser. | NEEDS-CHECK (parser syntax is documented externally, not in the OpenAPI file; "The query parser will return errors for invalid queries" is). Mitigation: `discover --verify-tags` executes `OG=(<variant>)`, `AD=(Varna Medical University)` with `count=0` and reports validity; queries are built entirely in `query_builder.py` from config. | Param description for `usrQuery`. |
| 2.23 | There is **no** h-index, JIF or journal-quartile field anywhere in the WoS Expanded response. | VERIFIED-FROM-DOCS (exhaustive schema walk) → h-index computed locally; JIF/quartile sourced from InCites only, never estimated. | Full `WosRecord` property tree. |

## 3. InCites API (Document Level Metrics API v2.0)

| # | Assumption | Status | Evidence / mitigation |
|---|------------|--------|-----------------------|
| 3.1 | Endpoints (all with `{format}` = `json` or `xml`): `GET /DocumentLevelMetricsByUT/{format}` (params `UT` comma-delimited, `ver=2` required, `esci=y|n`, `schema=wos`), `POST /DocumentLevelMetricsByUTforWOS/{format}` (body `{UT:[...], esci, schema}`, max 5000 UTs/request), `GET /DocumentLevelMetricsByInstitutionId/{format}` (`year`, `startingrecord`, `recordcount` 1–100, `ver=2`, `schema` enum, `esci`), `GET /DocumentLevelMetricsByInstitutionIdRecordCount/{format}` (`year ≥ 1980`), `GET /CheckValidUTs/{format}`, `GET /InCitesLastUpdated/{format}`. | VERIFIED-FROM-DOCS | `paths` + parameter tables. |
| 3.2 | Response envelope: `{"api":[{"name":"IncitesWebServices.<fn>","rval":[ {...} ]}]}`. | VERIFIED-FROM-DOCS | Examples + `MetricsByInstitutionIdResponse`. |
| 3.3 | Per-document fields exposed: `ACCESSION_NUMBER` (15-char UT), `DOCUMENT_TYPE`, `TIMES_CITED`, `JOURNAL_EXPECTED_CITATIONS`, `JNCI`, `IMPACT_FACTOR`, `HARMEAN_CAT_EXP_CITATION`, `AVG_CNCI`, `ESI_HIGHLY_CITED_PAPER`, `ESI_HOT_PAPER`, `IS_INTERNATIONAL_COLLAB`, `IS_INSTITUTION_COLLAB`, `IS_INDUSTRY_COLLAB`, `OPEN_ACCESS` (Gold/Green/Bronze/Hybrid/""), `RNUM`, `PERCENTILE[]{SUBJECT, CODE, CATPERCENTILE, IS_BEST, CAT_EXP_CITATION, CNCI}`. | VERIFIED-FROM-DOCS | `components.schemas.Record`, `Percentile`. |
| 3.4 | The institution for `DocumentLevelMetricsByInstitutionId*` is resolved **from the API key**; there is no institution parameter. Publication years ≥ 1980 only. | VERIFIED-FROM-DOCS | Endpoint description + `year` param doc. |
| 3.5 | **Not exposed by this API version:** researcher-level (ResearcherID/ORCID) indicators, organization-level aggregate indicators (h-index, totals), journal quartile (`Q1..Q4`) as a named field, and the JIF *edition year*. | VERIFIED-FROM-DOCS (exhaustive path/schema list) → per-researcher stats computed locally from harvested records; h-index local; quartile derived from `CATPERCENTILE` **only if** `quartile_from_percentile.enabled` is true (default true, documented thresholds Q1>75, Q2 50–75, Q3 25–50, Q4≤25 — clearly labelled as *derived percentile band, not the official JCR quartile*); JIF edition year left empty unless supplied in config (`incites.jif_edition_year_label`). | Path list of the snapshot. |
| 3.6 | `IMPACT_FACTOR` semantics: "Journal Impact Factor for the publication year" per the schema description; whether your subscription returns it for all years/journals is subscription-dependent. If absent/empty → field left empty + warning; never estimated. | VERIFIED-FROM-DOCS (description); subscription scope → runtime check via `discover`/`stats` warnings. | `Record.IMPACT_FACTOR`. |
| 3.7 | `TIMES_CITED` from InCites is labelled `source=InCites.TIMES_CITED` and reported side-by-side with the WoS Core Collection count; differences are flagged with the note that database coverage differs. | Design decision based on 3.3 + 2.12. | — |
| 3.8 | Quota/rate headers for InCites are not documented in the spec. | NEEDS-CHECK → all response headers are captured and logged; nothing depends on them. | Absence in spec. |
| 3.9 | Error codes 401/403 (invalid key / subscription out of scope) produce non-JSON or `ErrorResponse` bodies; handled with explicit messages. | VERIFIED-FROM-DOCS (`components.schemas.ErrorResponse`, security scheme). | Snapshot. |

## 5. Things this tool explicitly does NOT assume

* It never guesses extra InCites endpoints — anything not in the discovered spec is unreachable through configuration only after you add it to `config/api_map.yaml` yourself.
* It never estimates or interpolates JIF, quartiles or h-index from partial data.
* It never filters out authors whose affiliation could not be confirmed (flag only).
* It never writes an indicator value without its provenance (source + retrieval timestamp).
